# 一分钟演示剧本

> 2026-10-22 更新：当前证据见 [第二轮完善记录](improvements-20261022-round2.md)，历史性能记录按日期保留，不作为本轮结果。

> 正式入口：`http://localhost:5173`。完整准备、账号和故障处理见 [demo-guide.md](demo-guide.md)。
> 演示前先运行 `scripts/seed-demo.mjs`，并分别用 `demo_owner`、`demo_editor` 登录两个相互隔离的浏览器配置或浏览器；同一配置中的普通窗口共享账号状态。

## 0:00 至 0:10 说明系统边界

在所有者窗口打开“毕业设计协同演示”空间，展示首页的继续工作与最近更新，再指向左侧独立的文档、白板、看板栏目。

话术：本系统使用同一套 `Element + Op` 引擎驱动三类应用；文档按段落协同，白板同步结构化卡片，看板同步列和任务卡片。

## 0:10 至 0:35 展示双端实时协同

1. 两个窗口同时打开“需求评审纪要”。
2. 所有者新增一个段落并输入“先持久化，再广播”。
3. 指出编辑者窗口无需刷新即可出现相同段落，并观察顶部连接状态和在线成员。

话术：每次修改都转换为带 Lamport 时钟的操作；同一元素并发修改按 LWW 确定唯一结果，不宣称字符级合并。

## 0:35 至 0:50 展示历史与恢复

1. 在所有者窗口打开历史面板并预览一个较早版本。
2. 执行恢复，观察两个窗口同步到恢复结果。

话术：恢复不会改写旧日志，而是计算状态差异并追加新的前向操作，因此恢复行为仍可审计。

## 0:50 至 1:00 收束证据

返回工作台，依次指出搜索入口、Markdown 导出和协同统计。

话术：当前版本 141 项 Java 测试、148 项前端单测、47 组真实浏览器验收通过，另验证了删除和恢复前后重启的数据一致性。菜单、文档查找、白板缩放与看板跨列移动都有对应实测记录。

性能被问到时如实说明：本轮 50 客户端 P95 首次 275.50 ms，隔离复测 199.85 ms；门槛保持小于 200 ms，复测余量很小，不能承诺各种负载下稳定达标。

## 被追问时的可复现证据

| 问题 | 现场证据 |
|---|---|
| 断线是否能恢复 | 本轮真实三账号流程中断约 30 秒后自动重连补齐，见第二轮报告的真实流程证据 |
| 服务重启是否丢数据 | 本轮连续四次启动验证正文、图片、导出、删除和恢复状态，见 `artifacts/round2-20261022/restart-persistence/summary.json` |
| 只读者能否绕过界面写入 | 前端禁用写入，同时服务端 REST 与 WebSocket 均返回拒绝，见最终三角色 Playwright 证据 |
| 并发后是否收敛 | 8 个副本连续 3 轮、每轮 1000 个混合操作乱序投递，规范哈希全部一致 |
| 性能结果从哪里来 | `artifacts/round2-20261022/server/maven-174859.log` 与 `maven-180808.log`，首次失败和复测均保留 |

## 现场故障处理

| 现象 | 处理 |
|---|---|
| 页面打不开 | 确认后端 `8080`、Vite `5173` 均在监听，并访问 `http://localhost:5173` |
| 看不到协作空间 | 确认使用演示账号登录，点击“刷新内容”；数据尚未准备时按 README 运行幂等 seed 脚本 |
| 历史条目不足 | 先新增或修改两个段落，等待顶部状态显示“已同步” |
| 第二个窗口没有更新 | 检查两个窗口是否打开同一内容，并确认连接状态不是“已断开” |
