# 答辩演示指南

> 2026-10-22 更新：本指南保留末尾 2026-09-20 历史演示记录，当前功能与验收结果见 [第二轮完善记录](improvements-20261022-round2.md)。历史性能数字不能作为当前版本结果。IDEA 与 VS Code 启动步骤见 [本地启动](local-development.md)。

本指南用于在 10–15 分钟内演示任务书范围内的完整系统：JWT 登录、空间角色、文档/白板/看板协同、断线恢复、历史、搜索、Markdown 导出和统计。不演示自由绘制、字符级 CRDT或其他范围外能力。

相关文档：[系统架构](architecture.md) · [REST API](api-reference.md) · [WebSocket 协议](websocket-protocol.md) · [部署说明](deployment.md) · [测试计划](test-plan.md)

## 1. 演示目标与角色

准备三个相互隔离的浏览器上下文：可使用三个浏览器配置文件，或一个普通窗口加两个独立无痕上下文。不要让三个角色共享 `localStorage`。

| 角色 | 建议用户名 | 空间角色 | 演示职责 | 密码记录 |
|---|---|---|---|---|
| A | `demo_owner` | `owner` | 创建空间、邀请、删除权限说明、历史恢复 | 仅保存在现场密码管理器/纸质备忘，不写入仓库 |
| B | `demo_editor` | `editor` | 协同编辑、白板移动、看板拖拽 | 同上 |
| C | `demo_viewer` | `viewer` | 旁观实时变化、证明只读限制 | 同上 |

用户名必须满足 3–32 位 `[A-Za-z0-9_-]`；密码至少 6 个字符，同时不能超过 72 个 UTF-8 字节，中文字符占多个字节。以上账号只用于本地演示库，不复用个人密码。

## 2. 演示数据准备

演示前一天在最终演示环境完成一次准备和彩排：

1. 分别注册 A、B、C；注册会各自创建“我的空间”；
2. A 创建空间“毕业设计协同演示”；
3. A 邀请 B 为 `editor`、C 为 `viewer`；
4. 在该空间创建且只创建三项内容：
   - 文档“需求评审纪要”；
   - 白板“模块关系梳理”；
   - 看板“答辩准备计划”；
5. 文档预置两段短文本，白板预置一张卡，看板预置“待处理”“进行中”“已完成”三列和少量典型任务卡；
6. 不预置大量无关数据，以免搜索和统计画面难以解释；
7. 记录三个账号能登录、三项内容的 `docKey` 和 `/api/health` 结果。

也可以按根目录 `README.md` 的“演示数据”步骤运行 `node scripts/seed-demo.mjs`。脚本从环境变量读取三个本地演示密码，通过 REST 和 WebSocket 正常链路创建同一组基线数据；稳定的操作身份使重复执行不会生成重复日志，并会输出三项内容的 `docKey` 与基线版本。

不要用手工 SQL 创建账号或操作日志。所有演示数据都必须通过产品 UI、REST 或 WebSocket 正常路径产生，保证权限、历史和统计一致。

## 4. 主演示流程

```mermaid
flowchart LR
    A[登录与空间角色] --> B[文档双端同步]
    B --> C[同段冲突收敛]
    C --> D[白板卡片移动]
    D --> E[看板跨列拖拽]
    E --> F[viewer 只读]
    F --> G[断线约 30 秒恢复]
    G --> H[历史回放与恢复]
    H --> I[搜索 / 导出 / 统计]
```

### 4.1 登录、空间与权限（约 1.5 分钟）

1. 在 A 窗口登录 `demo_owner`，进入“毕业设计协同演示”；
2. 指向成员面板，说明权限来自空间而不是平台全局角色；
3. 展示 A 为“所有者”、B 为“编辑者”、C 为“只读者”；
4. 简要说明只有 owner 能邀请成员、删除内容及从回收站恢复；editor 可创建、编辑和恢复历史版本，viewer 只读。

讲解句：

> 系统先用 JWT 确认用户身份，再按空间成员表判断每一项资源权限；WebSocket 写入也会逐次重查角色。

### 4.2 文档双窗口实时同步（约 2 分钟）

1. A、B 同时打开“需求评审纪要”；
2. 确认双方顶部在线成员数/头像已包含两个连接；
3. A 修改第一段为“确认 WebSocket 实时同步”；
4. B 不刷新页面，观察第一段即时变化；
5. B 点击“添加段落”，输入“编辑者补充：历史记录可追溯”；
6. A 不刷新页面，观察新段出现；
7. 轻点段落上移/下移，说明排序也是普通字段操作。

屏幕证据：两个窗口标题一致、正文一致、在线成员可见。

### 4.3 同段冲突与收敛（约 1 分钟）

1. A、B 各自聚焦同一个短段落；
2. 倒数后近同时输入两个不同的完整短句；
3. 停止输入，等待双方显示完全一致的一个结果；
4. 刷新其中一端，再次确认结果不反转。

讲解句：

> 当前版采用元素级 LWW，完整元素按 `(counter, replicaId, opId)` 选择获胜状态。同元素的并发属性修改可能覆盖；不同元素独立保留，不提供逐字符合并。

不要提前承诺 A 或 B 必然获胜；胜者由实际 Lamport 时钟决定。重点是两端最终一致且刷新后稳定。

### 4.4 白板卡片同步（约 1 分钟）

1. A、B 打开“模块关系梳理”；
2. A 点击“添加卡片”，输入“WebSocket 实时层”；
3. A 选择一个颜色并拖动卡片；
4. B 观察文本、颜色和位置同步；
5. B 调整卡片大小，A 观察变化。

说明白板范围是结构化卡片及其几何字段，不包含自由绘制。

### 4.5 看板拖拽（约 1 分钟）

1. A、B 打开“答辩准备计划”；
2. A 在“待处理”点击“添加卡片”，输入“完成最终演示”；
3. A 使用卡片拖动按钮把它移动到“进行中”；
4. B 观察卡片跨列同步；
5. B 将卡片移动到“已完成”，A 观察最终位置；
6. 可补充演示同列上移/下移，避免只展示鼠标拖拽。

### 4.6 viewer 只读（约 1 分钟）

1. C 打开同一文档或看板；
2. C 能看到 A/B 的实时结果和历史入口；
3. 指出顶部“当前以只读角色查看”提示；
4. 确认标题、正文和卡片均不能修改，“恢复到此版本”不可执行；
5. C 可执行查看历史和导出，证明“只读”不是“不可访问”。

不要通过开发者工具伪造写请求作为主演示；权限拒绝已有自动化和协议测试支撑，答辩界面以清楚、稳定为主。

### 4.7 约 30 秒断线与恢复（约 1.5 分钟）

为保证可控，选择 B 窗口演示：

1. 记录 B 当前内容和连接状态；
2. 在 B 的浏览器 DevTools Network 中切换为 Offline，保持约 30 秒；
3. 离线期间 A 新增段落“断线期间由所有者写入”；
4. B 窗口应显示连接异常/重连状态，编辑被停用；
5. 约 30 秒后恢复 Online；
6. 等待 B 自动重连，不手动刷新；
7. B 应补齐 A 的新段落，双方内容与版本继续一致；
8. 最后刷新 B，证明状态来自服务端持久化而非仅留在内存。

讲解句：

> 客户端携带最后版本请求增量；版本游标无法连续补齐时，服务端自动退回全量快照。心跳和指数退避负责发现异常并恢复连接。

### 4.8 历史回放与恢复（约 1.5 分钟）

1. A 点击“历史”；
2. 在时间线中选择断线演示前的一个版本；
3. 只预览时指出当前 `rev` 和该版本内容；
4. 点击“恢复到此版本”，在确认对话框选择“确认恢复”；
5. 观察 A、B 当前内容同步到目标状态；
6. 再打开历史，指出刚才的恢复本身也产生了新操作，没有改写旧历史。

若目标版本会删除刚才新增的段落，提前说明这是预期差异，不是数据丢失。

### 4.9 搜索、导出与统计（约 1 分钟）

1. 返回工作台，在搜索框输入预置正文关键词“WebSocket”；
2. 打开命中项，说明搜索范围限于当前用户已加入空间；
3. 在文档中点击“导出”，打开下载的 `.md`，快速展示标题和正文；
4. 返回工作台的“协同统计”，展示空间数、内容数、操作数、应用分类、操作分类和贡献者；
5. 强调数据来自未软删除的可见文档与追加操作日志。

### 4.10 本轮使用体验补充（可选 2 分钟）

1. 返回空间首页，指出“继续工作”是最近打开记录、“最近更新”是当前空间最近修改；从左侧依次进入文档、白板、看板，展示正文摘要、实际画布缩略图和任务列分布。
2. 文档使用 `Ctrl+F` 查找正文，按 `Enter` 跳到下一处，`Esc` 返回原编辑位置；这些操作不生成新版本。
3. 白板切换 50% 缩放后拖动卡片，另一窗口看到相同的实际位置；点击“适应”浏览全部内容。缩放和平移只改变本机视图。
4. 看板使用卡片“移至列表”跨列移动，随后用顶部“跳转列表”查看目标列；同名列表有序号区分。
5. 用 owner 删除一份专门准备的演示副本，从回收站恢复并打开，核对正文和历史仍在。不要删除原始演示基线。

另一标签页切换账号会同步退出旧账号编辑页；演示 owner/editor/viewer 时应继续使用相互隔离的浏览器上下文，而不是同一浏览器配置中的三个普通标签页。

## 5. 讲解主线

答辩时可按以下四句话贯穿全程：

1. 三类应用统一建模为元素和字段，减少了三套独立同步逻辑；
2. 新版元素级 LWW 在同一组有效操作最终送达、规则相同且编辑停止后收敛；
3. 操作先持久化再提交内存和广播，快照加日志支持重启与历史恢复；
4. JWT 解决身份，空间角色解决资源权限，断线通过版本游标进行增量或全量恢复。

## 6. 失败兜底

| 现场问题 | 立即动作 | 恢复后如何继续 |
|---|---|---|
| 页面打不开 | 检查 `/api/health` 与 Vite 终端 | 后端正常则重启 Vite；后端异常看启动日志 |
| 登录提示过期 | 在对应窗口重新登录 | 重新进入原空间，数据不会因 token 失效丢失 |
| WebSocket 一直重连 | 刷新一次并检查 `/ws` 代理/后端日志 | 连接恢复后从“在线成员”步骤继续 |
| 某个窗口状态不同 | 停止继续输入，点击刷新或触发全量重载 | 对照另一端和历史最新 `rev` 后继续 |
| 下载被拦截 | 允许当前站点下载，再点“导出” | 不更换浏览器或临时修改代码 |
| 历史选择错版本 | 重新打开历史并选正确版本 | 恢复是追加操作，可再次恢复，不需改数据库 |
| 断网开关影响所有窗口 | 只在 B 的 DevTools 中设置 Offline | A 保持在线完成断线期间写入 |
| 投屏太小 | 浏览器缩放到预先彩排值 | 不临时改 CSS |

禁止现场执行删库、手工改 `operation_log`、清空浏览器所有数据或临时编辑源码。确需复位时，优先关闭三窗口并重新登录预置账号，重新打开已准备的三项内容。

## 7. 快速复位步骤

1. 确认 MySQL 与后端仍在运行；
2. 调用 `/api/health`；
3. 三个窗口分别重新登录；
4. A 进入“毕业设计协同演示”，核对成员角色；
5. 打开三项预置内容并刷新一次，等待连接就绪；
6. 在历史中选择预先记录的基线版本并恢复；
7. 删除演示过程中额外创建的临时内容时，只用 owner 从 UI 软删除；
8. 从文档双端同步步骤重新开始。

如果基线恢复尚未真实彩排，演示前不能把它视为可用兜底。
